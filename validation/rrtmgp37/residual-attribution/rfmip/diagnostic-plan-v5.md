# RFMIP SW residual diagnostic v5 — prepared, not run

This successor plan preserves the earlier v1/v2 plans and failed/passing evidence. It is a preparation artifact only: no diagnostic driver build or solver call has been performed for v4, and no authorization is embedded here.

If separately authorized, one isolated driver build will capture broadband source vectors before and after the RFMIP normalization, optical properties, solver fluxes before NetCDF output conversion, and written outputs. The two possible solver calls are ordered: current pinned coefficients first, then the selected old-solar coefficient counterfactual only if the current call is successful and bitwise identical to the retained current control. The old-solar file changes pinned solar source arrays only. Captured gas optical properties must remain bitwise identical between arms; a difference fails the diagnostic. This is not a claim about the unknown generation source for the published `RTE-RRTMGP-181204` label.

The driver normalizes each profile's entire 224-g-point source vector using broadband `total_solar_irradiance`: its denominator is the sum of the full vector, not a spectral-band subtotal. Before allowing a second call, the proposed runner checks all 135 requested `(experiment, site)` records, finite positive TSI and source denominator, and post-normalization closure against TSI with the explicitly recorded roundoff bound `32 * eps64 * 224 * max(1, |TSI|, sum(abs(source_post)))`.

Every residual calculation reports the float64 prewrite value, float32 stored value, published float32 value, and the nearest-float32 rounding interval around the published target. This is diagnostic only. The existing strict threshold remains `abs(delta) > 1e-5`, `rtol=0`; neither thresholds nor outputs are modified.

The runner is one-use and approval-gated. It also checks the linked diagnostic executable SHA immediately before each launch, immediately after persisting each solver return code, and at terminal completion. It requires the diagnostic and original executable ldd closures to match the separately frozen prebuild closure (including the absolute ELF loader), before and after linking. Compile/link return codes are fsynced before log or executable hashing. It checks the float32 cast of every captured written RSD/RSU profile at all 61 levels against the saved output and stops on any mismatch; at the selected residuals it reports ordered-float32 ULP distances as well as rounding intervals. It refuses an existing output root, fsyncs receipts, records process IDs at launch and return codes immediately after process completion before postprocessing, kills process groups on timeout/error, and pins all source/data/coefficient/input/selector/CSV/capture-format/object/archive/module/compiler/runtime-library files. It uses a controlled environment and requires the linked diagnostic executable's resolved runtime-library closure to match the original executable. It compares each arm to its matching retained stage-v7 control over the complete output arrays.

The strict RFMIP mismatch remains unresolved. This diagnostic can distinguish where current-vs-old-solar calculations first diverge and whether storage rounding explains any selected cells. It cannot establish the historical source-generation code or attribute a remaining discrepancy to the WRF port.
