# PR70 serial `em_real` build scaffold

This is a fresh, isolated GNU serial build scaffold for the current PR70 source. It is prepared for the later actual-wrapper same-state audit; it contains no compiled WRF executable and no forecast execution. The source is a detached worktree at commit `1cb6920a43d8ba10ecfa179487839f9df7022cb4`, with 7,034 tracked files pinned in `source-manifest.json`. `WRF/configure.wrf` is ignored by Git, so it is separately pinned at SHA-256 `6a2fcd322bbff92ff61a141671d492eb8d74e3d56af28582306c024775b89c68`.

The configuration comes from the previously successful GNU serial SCM build. It uses GNU Fortran 13.3, default 4-byte WRF real, `-O2 -ftree-vectorize -funroll-loops`, with OpenMP disabled and `DMPARALLEL` commented out. Its only local configure difference from the official serial config is the RRTMGP module include path. The donor had built `em_scm_xy`; this scaffold deliberately performs a full clean `em_real` build from the PR70 source, so no donor object or executable is reused. A prior serial `em_real` build of this exact PR70 source was not found. The serial `em_real` ABI must be confirmed from this build's compile log, output symbols, and runtime library closure before any audit use.

`toolchain-dependency-inventory.json` pins the compiler/build tools, NetCDF links and libraries, and 48 resolved runtime libraries from the serial donor. The shared NetCDF/system dependency tree is referenced by immutable absolute paths and hashed; it is not copied. The build runner’s ordinary invocation only performs source/config/dependency checks. `--execute` is a single-use, 1,800-second full compile (`csh -f ./compile -j 12 em_real`) and has not been invoked. It records the compiler return code before postflight analysis and rejects stale outputs, tracked-source changes, MPI-linked output, missing target objects, missing executables, or missing WRF success footer.

The separate same-state case is staged by the parent-owned workflow at `build/udm37-current-matthew-serial-audit-v1`; that staging is not part of this build scaffold. The source-selection and case details remain subject to parent review; no RTE calls have been made here.
