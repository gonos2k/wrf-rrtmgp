# 실제 동일 상태 RRTMG4 / RRTMGP37 진단 비교

PR #185 다음 단계로 **청천·액체 구름의 LW/SW 네 비교와 두 구름
seed 대조를 실제 실행**했다. 6개 프로세스에서 원 RRTMG4와 공용
RRTMGP37을 각각 호출했으므로 실제 엔진 호출은 12회다. 새 caller
객체 컴파일·링크 각1회이며 기존 WRF/RTE 라이브러리를 재사용했다.
새 WRF 예보·24시간 실행·Mie 계산은 없다.

**이 비교 구현은 선언한 상태 범위에서 완료**다. 생산 소스·기본값·
광학계수·number1의 LW37/SW37 보호조건은 유지한다. 4번 결과를 예보
경향에 적용하지 않으며 일반 4/37 결합예보 지원을 추가한 것이 아니다.

## 공통 상태와 명시적인 진단 구름

대기 입력은 보존된 주간 source65100초 기주의 LW 압력·온도·건조
기준 VMR 배열이다. 두 엔진 모두 **같은 121층 전체 대기와 확장층**을
사용한다. 결과를 평가하는 WRF native 범위는 59층·경계60까지다.
원 SW의 다른 상단 확장 설정과 LW 확장 설정을 섞지 않는다. 실제
입력 계보와 생성 배열은 실행 receipt와 검사기에 연결했다.

| 항목 | 공통으로 공급한 정의 |
|---|---|
| 대기 | 같은 층·경계 압력, 층 온도, H2O/CO2/O3/N2O/CH4/O2의 dry VMR |
| 청천 | 모든 수상체 물경로와 CF=0 |
| 액체 구름 | native30층만 CF=1, LWP=10g/m², 유효반경21.5μm; 나머지 물경로0 |
| 지표 | 같은 LW skin temperature·회색 방사율, SW 가시/NIR direct/diffuse 알베도 |
| 태양 | 같은 mu0≈0.05036558, solar constant≈1384.9066W/m², 거리 보정1 |
| 에어로졸·기타 | aerosol/ice/snow/rain/CFC=0 |
| 구름 표본 | 각 엔진의 모든 spectral point에 동일한 CF0/1 배열을 명시 |

액체 상태는 **원래 WRF 구름을 그대로 재현한 상태가 아닌 명시적
진단 변형**이다. 같은 기체·온도·지표에서 액체 성분을 더하는 비교다.
21.5μm는 두 optics의 입력 범위 안에 있다. PR #185의 조건부 참조는
그 적용 범위대로 유지하며 새 광학 적분을 반복하지 않았다.

RRTMGP SW 인터페이스는 TLEV/TSFC를 소비하지 않는다. SW trace의
그 자리에는 placeholder가 있으므로 LW용 물리 입력인 것처럼 비교하지
않았다. RRTMG LW export의 가열률 배열 끝에는 반환층 이외의 여분 원소가
있으므로 실제 반환하는121층을 검증하고, 최종 평가는 native59층만 쓴다.

## 기체 분자수는 실제 소비 지점에서 맞췄다

공통 VMR만 공급해도 두 엔진의 압력→분자수 변환은 상수·산술 정의가
다르다. 이번 진단은 **RRTMG4의 기존 pressure/VMR molecular-column
규약**을 공통으로 선택했다. 그 REAL32 계산의 분자수를 37의 선택형
기체량 인자로 전달할 수 있도록 진단 gas-mass bridge로 환산했다.

이 bridge는 **진단 기체 분자수의 단위 전달**이다. host 건조 층질량·
밀도·number를 고치지 않는다. 원 host 질량과 열용량은 별도 배열로
보존한다. RRTMG4의 질량 규약이 물리적 정답이라는 승인도 아니다.
4의 실제 `COLDry/COLDRY` 및 WKL과 37의 `GAS_COL_DRY`·실제 VMR을
대조했다. 최대 dry-column 상대차는 **5.2176e-8**이다.

4/37의 배경·broadening 처리, 기체/구름 계수와 분광 격자는 각 엔진의
고정 모델 정의다. 예를 들어 37의 명시 N2와 4의 나머지 broadening
혼합물은 같은 내부 객체가 아니다. 따라서 아래 차이를 동일한 optical
properties에 대한 순수 수송 solver 오차라고 부르지 않는다. 각 계수
버전과 실제 소비 배열을 보존해 엔진의 광학·분광·수송 차이로 구분한다.

## 실제 결과: 37−4의 signed 차이

경계 지표는 같은 위치의 순하향 `DN−UP`이다. 기주 순수렴량은 같은
native top의 net에서 지표 net을 뺀 값이다. 가열률은 양쪽의 플럭스
수렴량을 **같은 host constant-κ Cstar**로 환산한 결과다.

| 진단 | 지표 순하향 W/m² | native상단 순하향 W/m² | native 기주 수렴량 W/m² | 공통 Cstar 가열률 최대 절대차 K/day |
|---|---:|---:|---:|---:|
| LW 청천 | +2.425273 | −6.429857 | −8.855130 | 0.220150 |
| LW 액체 | +1.912070 | −6.462668 | −8.374738 | 0.795493 |
| SW 청천 | −2.952134 | −0.296200 | +2.655933 | 0.036899 |
| SW 액체 | −1.406163 | +0.254489 | +1.660653 | 0.136990 |

전체 UP/DN/net과 층별 signed 값은 [result.json](result.json)에 있다.
각 엔진의 cloud-minus-clear도 별도로 계산한다. 이는 **고정 상태에서
정의한 구성의 차이**이며 관측 오차나 실제 예보 편향이 아니다.

SW 확장 상단의 요구 입사량 S×mu0는 약69.75162789W/m²다. 37의 실제
상단 DN은 이에 일치하며, 4는 native 분광합·REAL32 산술에서 약9.64e-5
W/m² 차이가 남는다. 이 입사 경계 잔차를 숨기거나 출력을 맞추도록
solar constant를 조정하지 않았다. native 상단의 약1.5W/m² 하향 차이와
이 훨씬 작은 확장 상단 산술 잔차도 서로 구분한다.

## 가열률 환산과 원래 엔진 결과를 분리한다

각 엔진의 원래 native 가열률과 열용량을 함께 보존했다. 4의 열용량은
실제 `heatfac`에서, 37은 호출한 pressure/cpd/gravity 정의에서 복원한다.
공통 Cstar는 입력 당시 host의 constant-κ 열용량이며 엔진 코드에는
강제로 적용하지 않는다. 각 층에서

```text
native H37 − native H4
= (Q37−Q4)/Cstar
  + Q37(1/C37−1/Cstar) − Q4(1/C4−1/Cstar)
  + 각 native 산술 잔차의 차이
```

를 검증한다. 결과 JSON의 단위는 K/day다. LW 액체의 native 가열률 최대
차이는 약0.806182K/day이고 공통 환산에서는 약0.795493K/day다. 두
최대값의 차이를 층별 환산항으로 대신 사용하지 않고, 동일 층의 모든
항을 signed 배열로 보존했다.

독립적인 native source 검사에서 최대 `C·H−Q`는 4 약1.92e-6W/m²,
37 약7.16e-15W/m²다. 사전에 선언한 각 정밀도의 source consistency
screen을 통과했다. 이는 엔진 전체의 참오차나 물리 허용오차가 아니다.
출력 정밀도·source 잔차와 실제 복사 엔진 차이를 분리했다.

## 입력 무변경·구름 표본·실행 identity

각 프로세스의 공통 물리 배열은 호출 전/4 후/37 후 snapshot이 바이트
동일하다. 입력 파일도 동일한 hash를 유지했다. 각 엔진의 실제 mask,
LWP, REL도 같은 CF0/1 정의인지 검사한다. 구름 두 사례는 37 seed를
17→98765로 바꾼 추가 호출에서도 같은 결과다. **같은 정수 seed를
넣었다는 이유로 부분구름 표본이 같다고 판단한 것이 아니다.**

[identity.json](identity.json)은 caller·링크 라이브러리·실행파일,
생산 소스, 4/37 계수, 입력·결과·프로세스 PID/시각/종료코드를 연결한다.
기존 연구 소스를 새로 빌드했다고 집계하지 않고 caller만 새로 컴파일했다.
해석기 개발 중 export 배열/placeholder에 대한 검사 범위를 고쳤으며,
실제 6개 기주 실행을 다시 수행하지 않았다.

## 이번 작업의 종료와 남은 적용 판단

선언한 청천/CF1 상태에서 **같은 입력의 실제 4/37 호출·native 경계
비교·열용량 분해·입력 무변경 검증은 완료**다. [평가 결정](decision.json)은
목표량별 차이와 수치 잔차를 근거로 이 구현 범위를 종료한다.

물리 허용량은 사용 목적과 승인 권한에 따라 따로 정한다. 원 LUT의
population/크기 정의, 실제 PSD·발생분율, 온도 의존성, 기존 PBL/전체
수지, RFMIP·LBLRTM FAIL, 일반 입력·혼합상·MPI·관측 및 최종 결합예보는
기존 상태를 유지한다. 같은 seed의 부분구름 비교나 일반 4번 예보
지원으로 확대하지 않는다. 기존 일곱 종료 조건을 변경하지 않았다.

```sh
python3 -I -S validation/rrtmgp37/same-state-engines/verify_saved.py
python3 -I -S validation/rrtmgp37/same-state-engines/test_saved.py
```

위 두 명령과 CI는 stdlib 저장 근거 재생이다. 새 실제 실행은 `build.py`와
`run.py`가 담당하며 각 출력 디렉터리가 새 경로여야 한다. 의존 build는
기존 `udm37-radiation-options-build-v1`이다. `retain.py`는 실행 자료를
보존하는 도구이며 새 모델을 실행하지 않는다.
