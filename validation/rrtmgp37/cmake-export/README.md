# GNU CMake export and traditional Make parity evidence

This change exports `wrf_rrtmgp` as part of the installed WRF target set and installs generated RRTMGP Fortran modules beneath an install-relative include directory. The two UDM host entry points now accept optional assumed-shape arrays with explicit WRF memory lower bounds. CMake generates the relevant UDM fields as `ALLOCATABLE`; the traditional GNU Make configuration defines `USE_ALLOCATABLES` but its generated `inc/state_struct.inc` still declares those UDM fields `POINTER`. The optional nonpointer assumed-shape dummy interface accepts both generated actual-argument forms while retaining the WRF memory lower bounds. This addresses the actual generated-type mismatch rather than assuming the Make fields are allocatable.

The patch is based on `bb56ec0ad5a0fbd2ef2027a291554fc40d6c7291` and has five modified source/configuration paths listed in `evidence.json`. Fresh GNU 13.3 builds used NetCDF-C 4.9.2 and NetCDF-Fortran 4.5.4, single precision, big-endian WRF records, `-O2 -ftree-vectorize -funroll-loops`, and the local NetCDF prefix. The evidence covers GNU serial ARW `em_real`; it does not establish MPI, OpenMP, GPU, another compiler, or forecast-duration behavior.

## CMake build, install, and consumers

The commands are collected in [`scripts/reproduce_cmake.sh`](scripts/reproduce_cmake.sh). From a clean patched source checkout, set `ROOT` to this RRTMGP workspace, `SRC` to the checkout, and optionally `BUILD`/`INSTALL` to fresh output directories. The checked-in `toolchain-repro.cmake` is a whitespace-normalized reproduction copy; `evidence.json` records the SHA256 of the exact tested toolchain file. The exact source overlay is included as `source-overlay.patch.gz` (extract with `gzip -dc`). The script configures Ninja Release with ARW `EM_REAL`, nesting `NONE`, `USE_MPI=OFF`, `USE_OPENMP=OFF`, and `USE_DOUBLE=OFF`; builds `wrf`, `real`, `ndown`, and `tc`; builds the `diffwrf_int` install helper and remaining default targets; then installs. The final installed package includes `libwrf_rrtmgp.a`, 26 RRTMGP `.mod` files, WRF executables, and exported `WRF::wrf_rrtmgp` and `WRF::WRF_Core` targets. The exported target uses the installed module directory and contains no source/build-directory paths.

The script configures two fresh consumers. [`consumer/rrtmgp-only`](consumer/rrtmgp-only) links only `WRF::wrf_rrtmgp`; [`consumer/core-plus`](consumer/core-plus) links `WRF::WRF_Core` plus `WRF::wrf_rrtmgp`. Both use `find_package(WRF CONFIG REQUIRED)`, import `mo_rte_kind`, initialize gas concentrations, and ran successfully with `INSTALLED_WRF_RRTMGP_CONSUMER_PASS 8`.

[`scripts/reproduce_standalone_columns.sh`](scripts/reproduce_standalone_columns.sh) builds the standalone test project with the same NetCDF prefix and runs only `wrf_rrtmgp_columns`; that CTest passed 1/1. It is a column-interface/regression test, not a full WRF runtime test.

## Bounded restart smokes and Make parity

The CMake-built serial executable ran two one-minute restarts successfully: RA37 with frozen optics enabled and RA4 with frozen optics disabled. Their output checks require exact `Times=2010-06-11_12:01:00`, the expected one-file schedule and `289x189x39` domain, matching variable names/layout/dtypes, no numeric fill markers, and finite numeric values. The CMake smoke is a structural/runtime check; it does not assert numeric value parity against the Make executable.

The RA37 frozen-off probe rejected the shared hail-positive restart before writing history, with `RRTMGP_INPUT_UDM_HAIL_OPTICS_UNSUPPORTED`. WRF's serial error path calls `STOP 'wrf_abort'` and returned process status 0. The raw validator receipt that incorrectly expected a nonzero return is retained; a separate classification receipt records the expected fail-closed result from the marker, STOP, no success/history, and no timeout. This is not counted as a successful forecast.

The fresh GNU Make build then ran the same two successful one-minute configurations from the shared 12:00 restart. The exact output byte arrays, all variable/global metadata, dimensions, and output time matched their corresponding PR30 GNU serial reference histories. RA37/frozen-on matched 211 variables and 61,252,177 numeric values; RA4/frozen-off matched 208 variables and 59,012,716 numeric values. Both used a 512 MiB child stack. The preserved runner is [`scripts/prepare_make_parity_v5.py`](scripts/prepare_make_parity_v5.py); it records preflight hashes and refuses to overwrite its prepared output directory.

For the historical run layout, that runner uses fixed absolute workspace paths under `build/pr-wrf-rrtmgp/build/udm-cmake-export-fix/make-parity`. Its default invocation prepares fresh cases, and `--run` executes them; do not rerun into the existing evidence directory. The prepared inputs/reference histories, exact commands, source/config/binary hashes, run results, and an independent whole-file recheck are included under [`receipts/make`](receipts/make). CMake command/build/install/consumer receipts and the bounded smoke receipts are under [`receipts/cmake`](receipts/cmake).

The build evidence retains earlier failures. The initial export-only configure/build identified the missing installed target export; the first complete CMake compile exposed pointer-versus-allocatable dummy incompatibility. The first install attempt lacked helper targets, so the final sequence explicitly built `diffwrf_int` and the remaining default targets before installing. These were resolved without expanding the five-file source patch.

No generated executable, object, module, or model history is included in this review package. `evidence.json` records scope and key receipt hashes; `artifact-index.json` and its standard-library verifier authenticate the packaged files.
