# Corrected paired 24-hour case: offline comparison

This is scratch evidence for the corrected RA4/RA37 paired case. The run receipt
reports `BOTH_VALIDATED`: both four-rank runs completed with zero return codes,
25 hourly histories from 2010-06-11 00Z through 2010-06-12 00Z, finite numeric
history arrays, and valid 12 h/24 h restart files. Inputs and the executable
were hash-checked before and after each arm. Executable SHA256:
`176f589d657ca87df670cef3429d7474e674f3e44445eb7886aed871e36bef8f`.
Reviewed runner SHA256: `ba5f6a790da31a5c4b7a3bfa5aaf40311be7149e2cc9eaf99b0c0b6cf1f07f43`.
Preflight SHA256: `0403bb5f94375a2eb5e888867e67a197c65bbc8916453ba8d16b41e6d5d0490c`.
The detailed execution receipt is `../../udm-current-24h-plan/execution.json`; all
input and per-history hashes are in `analysis.json`.

The comparison uses all 54,621 cells on the full 289×189 unstaggered mass grid,
weighted by `AREA2D` (sum 2.18484e13 m²). RA4 and RA37 began from the same fields
and boundary data. The only namelist changes are RA physics selectors and
RA37's experimental frozen-optics mode/table. Thus these are paired coupled
trajectories; atmospheric feedback means this is not a same-state solver test
or an observational forecast-skill result.

and 100 are skipped because histories omit the needed variables. GLW=LWDNB and
OLR=LWUPT pass in both arms at all 25 times (100 checks). RA37 SWDOWN=SWDNB
