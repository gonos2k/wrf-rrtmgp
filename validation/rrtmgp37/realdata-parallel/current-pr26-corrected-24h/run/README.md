# Corrected paired 24-hour real-domain trial (prepared, not run)

This scratch plan uses the fresh GNU dm+sm executable built from the corrected SR-row source. The RA4 case uses legacy/generic radii and precipitation optics (frozen-optics mode defaults off); the RA37 case uses UDM-native radii and frozen-optics mode 1. Both use the same UDM27 initialization, boundaries, 60-second timestep, damping, 4 MPI ranks, 1 OpenMP thread, and interval from 2010-06-11 00:00 through 2010-06-12 00:00. History output is hourly, with restart writes at 12 h and 24 h.

The executable hash is `176f589d657ca87df670cef3429d7474e674f3e44445eb7886aed871e36bef8f`. Its source provenance is in `build/udm-sr-row-dm-sm/source-provenance.json`; this build includes the `sr(ims,j)` correction, and its source hash is checked again before any execution. The input and boundary hashes are `5ef7abe34c516fba107f346bdbdb3777edacb5d48493df467ea2dd8bcf6a75ff` and `e687b73730ab9a2cee4842e1a92b225a4edb074ba080b6053d96d81ec1731a2d`. The frozen table hash is `8cb00850c3f885f5ec0306563c1ec0a55b512478a7395d626c1c99cebf280583`; RRTMGP g128/g112 and cloud-boundary tables plus legacy RRTMG tables are also SHA-pinned in `preflight.json`.

Current CFC wiring is used. The older PR20 six-gas omission does not describe this executable. This is a corrected RA4-versus-RA37 coupled trajectory comparison, not an official-pristine-WRF comparison. It does not replace or modify any archived comparison metrics. The distinct `cldf_diag` `intent(inout)` correction may also affect above-cloud-top UDM state relative to pristine WRF; that effect is outside this pair and is not attributed to the SR fix.

The prepared inputs are isolated copies in `cases/ra4` and `cases/ra37`; coefficient/static assets are symlinked read-only from the pinned run tree. `preflight.json` hashes both namelists, input/boundary files, and each of the 90 staged static assets per case, including each symlink target and resolved target hash. It also verifies the input time and boundary-file `Times`, `md___thisbdytime...`, and `md___nextbdytime...` through the requested endpoint. No forecasts have been launched. The runner refuses to overwrite cases or repeat a prior execution, verifies staged hashes before and after each run, locks against simultaneous invocations, clears every `WRF_RRTMGP_*` and `WRF_UDM_BOUNDARY_CAPTURE*` variable, and sets one OpenMP/OpenBLAS thread. It launches RA4 first and will only advance to RA37 after verifying all four rank success markers, the exact 25 hourly `Times`, finite numeric history arrays, and the 12-hour/24-hour restart files. A failure is recorded and returns nonzero. Execution occurs only when explicitly requested:

```sh
python3 build/udm-current-24h-plan/run_pair.py --execute
```

The optional per-cell hydrometeor audit is deliberately disabled because it can emit large negative-cell logs over this run. No physics or tolerance adjustments are made to collect diagnostics. The completed trial is recorded in `execution.json` (status `BOTH_VALIDATED`): both arms exited zero, all four ranks reported success, all 25 hourly outputs were present at the exact timestamps and finite, and both restarts (12 h and 24 h) had exact timestamps and finite numeric arrays. Staged case assets and pinned sources/data matched before and after each arm. The two initial history records remain the archived byte-identical initialization; this evidence does not turn later coupled differences into same-state radiation differences.

The follow-up own-arm 12:00→13:00 checks are in `restart-v2/execution.json`. RA4 and RA37 each restarted only from their own 12:00 checkpoint and matched their continuous 13:00 output exactly across all 201 and 204 numeric fields, respectively. Their variable sets/dimensions matched; all rank success markers and physics attributes matched. The only global attribute difference was the expected `START_DATE` anchor (00:00 continuous versus 12:00 restart); all variable attributes matched. The first restart attempt's prelaunch guard false positive is preserved in `restart/execution-v1.json`; it launched no model process. Aggregate bounded-negative correction log summaries for the production RA37 path are in `hydro-correction-summary.json`. These are sums of wrapper-reported layer-cell path corrections across radiation calls, ranks, phases, and hydrometeor species; they are not water loss, a water-budget estimate, or an area-integrated mass. LW and SW are separate radiation paths, so their figures must not be combined. The run used debug level 0, so the absence of `RRTMGP_CLEAR_CONDENSATE_EXCLUDED` messages cannot establish that no zero-cloud-fraction condensate was omitted. Frozen-optics mode 1 was enabled in RA37 and suppresses the fallback graupel-optics-omitted diagnostic; absence of that message does not establish that graupel was absent.
