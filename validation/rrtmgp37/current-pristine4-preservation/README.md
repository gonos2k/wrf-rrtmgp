# Current-source default RRTMG4 preservation check

The current WRF source was built as PR74 worktree commit `b7b5f6f9cd657408e3bde3018d7e882ab3e4bce3`; its WRF source tree is identical to PR74 HEAD `5f3034e9c43209a352977da4885a3fc15b46c532`. A current-source, serial GNU build ran the existing official WRF 4.8.0 UDM4 control and mixed SCM inputs for 60 seconds each, with legacy RRTMG4 selected. Both processes returned 0 and their seven-record NetCDF outputs matched the archived official pristine histories byte-for-byte. Each also matched the previously validated source54 output. This is a narrow RA4 preservation result for those two SCM cases.

The package includes the dry preflight and frozen runner, root’s once-only authorization, per-case process records and full comparison receipts, source/build/configuration pins, staged-input manifest, official pristine comparison, source54 receipts, and independent prelaunch and terminal reviews. The two current-run histories are included as deterministic gzip files because their bytes equal the official outputs already archived elsewhere. They are not new pristine output files.

Run `python3 verify_evidence.py` from this directory to check the closed package roster, every packaged file hash, gzip decompression hashes, receipt/provenance links, seven `Times` values per case, all-208-variable equality records, full-history SHA equality, and both process exit records. The verifier uses only the Python standard library. It validates recorded comparison evidence; it does not reopen the NetCDF arrays. To independently reopen the compressed histories with NetCDF4, decompress each `.nc.gz` to a temporary `.nc`, then use `netCDF4.Dataset` to inspect data model, variables, dimensions, attributes, masks/fill values, and raw arrays against a local copy of the pinned official file.

Scope limits: two 60-second SCM fixtures only. This does not establish long-forecast or restart preservation, broader atmospheric accuracy, or a general result for all RRTMG4 configurations. No executable, full WRF source manifest, baseline NetCDF duplicate, or large model inputs are included; their absolute paths and SHA-256 pins are recorded in `external-source-pins.json`.
