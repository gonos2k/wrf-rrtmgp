The installed `WRF::wrf_rrtmgp` target did not propagate the GNU OpenMP runtime dependency from the vendored RRTMGP static library. Linking the vendor target publicly to `OpenMP::OpenMP_Fortran` only when `USE_OPENMP` is enabled carries the required compile/link usage through WRF and installed-package consumers while leaving non-OpenMP builds unchanged. The registration receipt pins the CMake edit.

Validation: fresh GNU CMake/Ninja OpenMP build/install, compile-flag inspection, vendor standalone builds with OpenMP on/off, adapter and column CTests, two installed consumer builds/runs without manual OpenMP flags, and three bounded one-minute RA37/MP27 runs. OMP1, OMP2, and OMP2 with the diagnostic callback interposer produced byte-identical histories; the interposer observed both workers executing the LW/SW radiation callback. This does not claim MPI/GPU coverage, long forecast validation, physical accuracy, or a speedup measurement.
