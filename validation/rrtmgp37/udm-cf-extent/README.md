# UDM cloud-fraction extent evidence

This bundle records the `UDM_CF_TOP`/`UDM_CF_SOURCE_STEP` diagnostic extent
contract. It does not switch the radiation cloud-fraction policy. The full
working vector remains `UDM_CLDFRA`; only levels through the recorded top are
known to have been written by `cldf_diag`.

`evidence.json` is the concise evidence index. It records the fresh GNU serial
build and all 21 staged production-source hashes, the separately rejected
overlapping build attempt, one-minute SCMs, all-call audit, independent
extent-limited B replays, focused native UDM tests, and a fresh mode-1 frozen
optics control run. Paths in `evidence.json` are workspace-root-relative; paths in `manifest.json`
use the isolated source-tree root for `WRF/...` and bundle paths. Large build
products are hash-indexed rather than copied; the large SCM receipt
with serialized history arrays is intentionally not copied into this bundle.
The eight small-control/mixed call-1/call-2 LW/SW raw captures are included, as
are corrected control/mixed analyzer outputs and the two extent-limited B
replay receipts. Input/result and history files remain hash-indexed rather
than duplicated.

The supported driver layout here has `kts=1`, so `UDM_CF_TOP` is a one-based
bottom-up native-layer count. `-1/-1` means no `cldf_diag` call, `0` records an
actual empty extent, and a positive value is the exact `ktop`. The partial
output dummy is `INTENT(INOUT)` so layers above `ktop` retain the caller's
initialization. This corrects the interface's partial-write semantics; it
does not alter the evaluated `1:ktop` range or radiation behavior, and it is
not evidence of an MPI-specific defect.

The current-only history field comparison is against the PR23 mode-0 `current`
outputs: all common arrays match exactly and `UDM_CF_TOP` is the only extra
field for option 37. Option-4 histories also match those outputs exactly.
The separate inherited 4/4 check uses a history generated with baseline WRF
executable SHA `08202d…`; it is not a comparison against the PR23 executable
SHA `097d…`. No `test_frozen_scm.py --baseline-wrf` comparison was used because
that harness expects the earlier direct-flux behavior to change.

Audit ratio summaries are generated by the corrected analyzer: both ratio
operands must be valid fractions in `[0,1]`, which excludes unknown layers
above `UDM_CF_TOP`. The original audit outputs remain preserved outside this
bundle; corrected analysis files and their provenance are recorded in
`evidence.json`.

MPI/restart, or physical-accuracy validation.
