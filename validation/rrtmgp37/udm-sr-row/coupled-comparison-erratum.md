# Erratum: 24-hour RA4–RRTMGP37 comparison is confounded by UDM `SR`

This note narrows the interpretation of the existing 24-hour paired comparison. The old runs, histories, JSON metrics, and receipts are preserved unchanged. The reported differences remain measurements of those runs; the RA4 reference has since been found to have an `SR` argument indexing error, so the differences cannot be attributed to radiation-physics differences alone. Re-evaluation against a corrected RA4 runtime is still required.

## Source finding

In `WRF/phys/module_mp_udm.F` at the PR20/PR21-era source, the call to `udm2d` in the all-radii/optional-diagnostic branch passes the current row, `sr(ims,j)`. The fallback branch passes the whole two-dimensional array, `sr`, to the row-level `udm2d` interface instead (`module_mp_udm.F`, lines 346–387 in commit `ca33525ad69af58302608d93362a83e698f37698`; the faulty argument is at line 380). When the fallback branch is selected (`has_reqc/has_reqi/has_reqs` not all one, or the optional diagnostic arguments are absent), the callee indexes that rank-mismatched actual as a one-dimensional row. This does not provide the intended `sr(:,j)` data for each outer-loop row.

`SR` is the frozen-precipitation fraction. UDM writes it from `snowncv/(rainncv+qmin)` when surface precipitation is present (`module_mp_udm.F:2723–2726`). Noah uses `SR(I,J)` as `FFROZP` when frozen-precipitation partitioning is enabled (`module_sf_noahdrv.F:876–887`), which feeds the snow/soil surface partition. Thus, a wrong `SR` row can change land-surface forcing and the later coupled trajectory. The error is in the RA4-side reference path identified by the bounded pristine comparison; this makes the old RA4 trajectory an unsuitable control for isolating RRTMGP radiation effects.

## Bounded evidence and interpretation limits

The official pristine WRF v4.8.0 versus PR21 RA4 restart comparison is a single 60-second step, from the same 2010-06-11 12:00 checkpoint to 12:01. In both MPI1 and MPI4 comparisons, 201/202 total output variables match exactly; `SR` is the only unequal variable. Its unequal count is 317 cells with maximum absolute difference 1.0. Receipts: `build/pristine-wrf-dm-sm/runtime-preflight/history-comparison.json` (SHA-256 `1e7c1746870b8947b3639c9c708b0585c658c212c30eb750b10413ea7f8f2d5d`) and `pristine-mpi1-mpi4-summary.json` (SHA-256 `ad9c2b07446fa21fe33f7c325d7052db8aef66bf18f2be95ab99ce0ce85039fe`). This bounded result shows the `SR` discrepancy in that one-step comparison; it does not measure the 24-hour effect or prove that all later residuals are caused by `SR`.

The earlier 24-hour metrics remain valid as measured differences between the archived output files. Examples from the unchanged report are area-weighted RMSE of 44.51 W m⁻² for SWDOWN, 6.68 W m⁻² for GLW, 7.47 W m⁻² for OLR, 0.207 K for T2, and 6.29 Pa for PSFC; later-hour L∞ maxima include 902.7 W m⁻² for SWDOWN, 96.7 W m⁻² for GLW, and 151.4 W m⁻² for OLR. They must now be labeled as coupled trajectory differences with a known RA4 `SR`/surface-partition confounder, not as residuals attributable to radiation physics. Other known differences remain: RA4 uses legacy generic-radius cloud optics and precipitation treatment, while mode 1 uses UDM-native radii and experimental frozen-particle optics for selected species. In addition, the PR20 six-explicit-gas-VMR implementation omitted four LW CFC species (CFC11, CFC12, CFC22, and CCl4), which were connected later in PR21; “21” identifies the PR, not a gas count. These differences are separate from the `SR` issue.

There is another independent scope limit for a future comparison against pristine WRF: the later `faf3ea0` change corrected `cldf_diag`'s `cldf` dummy from `intent(out)` to `intent(inout)` because only levels `1:ktop` are diagnosed and values above `ktop` must retain the caller's initialized state. This can affect UDM behavior above cloud top relative to pristine/older RA4. It is not evidence for, or part of, the `SR` indexing defect, and its impact has not been quantified here. A corrected RA4 comparison should account for both source differences separately.

## Scope of follow-up correction

After the corrected runtime is validated, revise only the interpretation of the real-data 24-hour comparison in `build/udm-frozen-24h-comparison/README.md` and any report that quotes those 24-hour deltas. Keep `metrics.json`, `ra4-24h-summary.json`, and all original run receipts as immutable historical evidence. A corrected, paired 24-hour RA4 rerun can establish a new comparison; it cannot retroactively turn the archived old RA4 trajectory into a valid radiation-only baseline. The one-step pristine evidence and unrelated SCM, standalone-column, and microphysics tests are outside this erratum's scope.
