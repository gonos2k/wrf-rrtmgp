# Read-only UDM27 / option-4 source review

Compared the official WRF v4.8.0 checkout at `build/pristine-wrf-v4.8` (HEAD `06d4240ae989cc3e50af412bb472df3d9048783c`) with the corrected working tree `build/udm-sr-row-work/WRF`. This is a source review only; no production files were changed and no long model run was started. The worktree contains the registered CF-extent changes plus an uncommitted SR-row edit and tests.

## Findings

- **A behavior change beyond the listed native37 fields / denominator initialization is present in `cldf_diag`.** The corrected source changes `cldf` from `INTENT(OUT)` to `INTENT(INOUT)` (`module_mp_udm.F:3384`), with the caller initializing `cldf(:)=1` before calling (`:1025`). The helper assigns only `1:ktop` (`:3395-3420`), so the patch now defines above-top values as the caller's initialized 1. Those values can be read later in melting/phase-change temperature terms (`:1136`, `:1160`, `:1184`, `:1196`, `:1216`, `:1241`, `:1266`) whose loop tops are species-specific and can exceed the cloud/ice `ktop` used by `cldf_diag`. In the official source, those elements became undefined on entry to an `INTENT(OUT)` dummy, so the old result was not a portable, well-defined baseline. The new behavior is a sensible preservation of the existing initialized working vector, but it can alter UDM runtime numerics in these above-diagnostic-top cases for both option 4 and 37. Treat it as a deliberate UDM correction with explicit scope/evidence, not as a strictly diagnostic-only change or a blanket original-4 preservation claim.
- **The `den1d` initialization is gated away from UDM27 + RRTMG4.** `den1d(k)=den(i,k,j)` is added before `udm_mp_effective_radius` (`module_mp_udm.F:470-475`). The radius routine runs only when all three `has_req*` values are nonzero (`:462`). In `module_physics_init.F:1076-1163`, UDM is absent from the legacy `use_mp_re` supported-scheme list; the UDM override sets those flags only for the explicit 37/37 pair (`:1121-1127`). Thus the new density feed is reachable for UDM37 when effective-radius support is enabled, but not for UDM27+RA4. The option-4 calculation remains skipped as before.
- **The SR row association matches the official shape.** The v4.8 source call passes `sr(ims,j)` to `udm2d` (`module_mp_udm.F:341-359`); the corrected worktree uses that same row section in all three optional-diagnostic dispatch branches (`:360-421`). `udm2d` consumes `sr` as a one-dimensional `ims:ime` row. This restores the same intended row association for every branch, including the no-diagnostic path, and avoids associating the full 2-D surface array at each j iteration.
- **Optional diagnostics are guarded and shaped consistently.** The host Registry declares `udm_cldfra` as an `ikj` field and step/top as `ij`; the UDM dummies use `(ims:ime,kms:kme,jms:jme)` and `(ims:ime,jms:jme)`. The outer routine initializes only the active tile bounds to `-1` (`module_mp_udm.F:317-319`), dispatches diagnostics only when cloud fraction and step are present and all `has_req*` flags equal 1 (`:357-359`), and tests top presence separately. The driver further requires all three optionals to be present and associated before forwarding them (`module_microphysics_driver.F:2808-2821`); otherwise it takes the legacy no-diagnostic call. Within `udm2d`, top/step and cloud fraction are reset to sentinel at entry, then written for columns reaching `cldf_diag` (`module_mp_udm.F:919-921, 1068-1073`). Clear/skipped columns therefore remain sentinel, while diagnosed columns expose all native levels, including the preserved above-top working value.
- **Physics-init changes relevant to RA4 do not select or initialize RRTMGP.** The two `has_req*` predicates broaden the supported radiation enumeration to include 37 (`module_physics_init.F:1080-1095`), then the UDM-specific flag override is restricted to the paired 37/37 case. `rrtmgp_init` is called only inside the `RRTMGP_*SCHEME` cases (`:2436-2442, 2555-2561`); option 4 continues through its existing RRTMG initialization calls. The paired-selection guard only rejects a one-sided option-37 configuration (`:2298-2303`). The added `name="RRTMG"` case in annual GHG lookup affects the new option 37; option 4 retains its previous mapping.

## Review limit

No compiler/runtime verification was performed during this review. The source-level conclusion is that optional fields, active bounds, and dispatch branches are internally aligned, and the denominator fix is dormant for UDM27+RA4. The `INTENT(INOUT)` change is a real cross-version semantic correction from an undefined above-top value to the caller's 1; equivalence evidence should explicitly cover its impact or document that the official result was undefined there.
