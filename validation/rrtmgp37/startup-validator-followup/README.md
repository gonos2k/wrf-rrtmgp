# Startup validation follow-up

The RUNNING journal write belongs to the child lifecycle guard. Storage failure stops the entire process group, including descendants after leader exit, and reaps the child before attempting a terminal receipt. Persistent storage failure preserves the original error and attaches observed RC when possible; storage durability itself cannot be guaranteed when the storage is unavailable.

Four actual production-runner dummy-process controls and 19 optics/passivity controls passed. The existing GNU serial REAL32 classic executable then ran one ideal and two 60-second candidate37 forecasts with the combined harness. Capture OFF/ON histories were byte-identical across all 211 arrays. The ON case passed all16 LW/all14 SW bands, independent LW path/radius optics and capped-SSA SW absorption invariance. No new build or Fortran physics change was needed for this validator patch.

`root-execution.json` pins the combined test script and actual process RC. `runtime.json` pins the reused executable, input and coefficients and records each arm. `result.json` reports the scoped result. These are engineering integration/passivity results, not Nc/PSD/LUT, RFMIP/LBLRTM or forecast-skill approval; there is no pristine or engine4 comparison in this two-arm run.
